> 版本：v0.3（2026-07-25）｜ 状态：开发依据
> 上游文档：`0725-产品细化.md`（当前设计汇总）、`0725-用户旅程&产品设计草案.md`、`0725-流程图草图.pdf`
> 配套文档：`docs/前端设计规范.md`（v2.2，页面与呈现权威）、`docs/API.md`（v0.2，接口契约）
> 变更摘要（v0.2 → v0.3）：资源改为双人各自储备（水滴/养料双方各得、阳光仅分享者）；照料改为整组扣除、双人各完成一次，取消缓冲期；新增仿抖音聊天页（互动模拟器迁址）；TA 自动照料（Demo）；新增「查看完整成长旅程」；花房 ×0 灰卡 +「重新种植」；花房双入口（AI 推荐搭配含送花意图与赠送花材 / 自由搭配）；发送花店附包装建议、用户备注与替代选项；新增演示重置与预置花材；CTA 改为「进入花园」+ 选择花园。

## 1. 背景与目标

两位好友或情侣把现实中拍到的花种进共同花园；日常聊天、视频分享和持续互动会积累**各自的**照料资源。双方分别完成照料后，花朵逐阶段盛放、收入花房，并可组合成一束由花店制作的实体花。

> 聊天让关系持续，花让关系被看见，花束让关系落到现实。

**MVP 目标**：以"抖音内程序"的页面形态跑通最小闭环（评委可完整体验：识花、互动获资源、双人照料、花开收藏、花束和花店出口，无需等待真实成长周期）：

```
相机拍照/上传 → AI识花(mock VLM+LLM) → AI科普页 →「进入花园」选择花园种下
→ 仿抖音聊天页(互动模拟器: 互发消息/分享视频/延续互动, 双方各自获资源)
→ 花园「我/TA」并列进度 → 我完成照料(提醒TA弹窗) → TA自动照料 → 双方完成即成长
→ 盛放「压花收藏」入花房 → 花房「AI 推荐搭配/自由搭配」→ 花束预览+搭配说明
→「发送花店」(扣减花材, ×0 灰卡可「重新种植」) → 抖音电商原型页(静态) → 闭环
```

## 2. Demo 设定与名词

- **程序形态**：抖音内程序，非独立 App。页面栈导航，**禁止全局底部 TabBar**。页面编号以《前端设计规范》§3 为准（P0 相机 / P1 分析 / P2 科普 / P3 花园 / P3a 资源明细 / P-chat 仿抖音聊天页 / P4 花房 / P5 花束预览 / P6 电商原型 / P7 弹窗层）。
- **入口**：① 相机（识图入口，本期实现，P0）；② 聊天页花园入口（本期以 **P-chat 仿抖音聊天页**呈现其叙事：聊天框下方「花园」入口）。
- **单用户 Demo**：固定用户「我」（me），虚拟好友「小葵」（ta）；唯一双人花园 `garden_id = 1`（启动播种）。**TA 为虚拟人，其资源入账与照料由系统按规则模拟**（见 F4）。
- **模型能力全部为 mock 适配器**（VLM/LLM/生图，契约见 API 文档 §4），可随时替换。
- 名词：水滴 / 阳光 / 养料 = 三种养成资源，**双人各自储备**；花房 = 已收藏花朵库存；花束方案 = 预览图 + 花材清单 + 搭配说明。

## 3. 功能需求

### F1 AI 识花（P0 → P1 → P2）
- P0：拍照或相册上传一张花朵图片（jpg/png，≤10MB）。
- P1：全屏分析流程（扫描光点 → 框选收缩 → 卡片上滑，保底约 2s），期间调用识花接口：VLM 返回品种/主色/辅色/置信度；LLM 返回科普文案；预生成 5 个成长阶段视觉资产（地栽版）。
- P2：展示品种名、主/辅色、置信度、科普正文、养护要点、「种入花园后的成长形态」横排图条；支持上滑展开（4:6 ⇄ 2:8）；右上 X = 放弃返回 P0。

### F2 种植
- P2 底部 CTA「**进入花园**」→ 选择花园半屏卡（标题「选择花园」，本期单选项「我和小葵的花园」）→ 种下，成功 toast 后进入 **P-chat 仿抖音聊天页**（评委由此看到真实产品的聊天入口叙事）。
- 品种与颜色自种植锁定；同一花园允许同时种植多朵未成熟花，不限品种。
- P3「去识花」入口卡 → 回 P0，可反复种新花。

### F3 资源获取（P-chat 互动模拟器；双人各自入账）
- 真实环境中资源由聊天行为自动产生；Demo 在 P-chat 底部「互动模拟器」提供三个按钮（API 1.11）：
  | 按钮 | 入账 | 来源文案 |
  |---|---|---|
  | 互发消息 | me 与 ta 各 水滴+1 | 「你们今天互相说过话，各获得 1 滴水」 |
  | 分享视频 | **分享者单方** 阳光+1（模拟器轮流 me/ta） | 「你分享了一条视频，获得 1 缕阳光」/「TA 分享了一条视频，TA 获得 1 缕阳光」 |
  | 延续互动 | me 与 ta 各 养料+1 | 「你们已连续互动 3 天，各获得 1 份养料」 |
- 资源不要求当天使用，可累积。MVP 不设每日上限（上游待确认项，配置预留）。
- P-chat 聊天区随互动追加模拟消息气泡（文本泡 / 视频卡泡 / 连续互动系统条），让评委理解资源来源；聊天框下方有「花园」入口 → P3。
- P3a 资源明细卡：三资源余额（**我的储备**）+ 来源事件流水（只展示事件，不涉及聊天内容）。

### F4 双人照料与成长（P3 花园页）
- 成长阶段固定：`种子 → 萌芽 → 幼苗 → 花苞 → 盛放`。**成长唯一取决于**：当前阶段双方资源条件各自达标，且**两人各自点击过一次「照料这朵花」**。不按天数/缓冲期自动成熟。
- 每阶段"每个人"所需资源（向日葵示例值，全局统一模板）：
  | 阶段 | 水滴 | 阳光 | 养料 |
  |---|---|---|---|
  | 种子 | 2 | 0 | 0 |
  | 萌芽 | 3 | 1 | 0 |
  | 幼苗 | 4 | 2 | 2 |
  | 花苞 | 5 | 3 | 3 |
- **照料语义**：当我的储备 ≥ 某朵花当前阶段需求时，该花「照料这朵花」按钮点亮；点击后**整组扣除**本阶段所需资源并记录我已完成；一份资源只投入一朵花的当前阶段。我已完成的阶段不可重复照料（409）。资源不足时按钮灰置并提示缺口。
- **并列进度**：植株卡以「我 / TA」并列展示（每项资源 ✓/✕ + 已完成/等待中），并给出状态提示语（如「你已完成今天的照料，等 TA 的资源到位，这朵花就会长大」）。
- **提醒 TA**：我完成照料且 TA 未完成时，弹出「提醒TA照料鲜花」弹窗（主按钮「提醒 TA」→ toast「已提醒 TA，等 TA 来照料」；次按钮「知道了」）。
- **双方完成即成长**：进入花园或照料时触发检查，花朵升入下一阶段；该阶段双方照料标记重置。阶段变化时播放成长动画并置「花园有新的变化，去看看吧」提示。
- **TA 自动照料（Demo）**：TA 储备 ≥ 当前阶段需求后延迟 8s 自动完成（`TA_CARE_DELAY_SECONDS`）；TA 储备不足则等待。TA 不可替我完成，我也不可替 TA 完成。
- **查看完整成长旅程（Demo）**：植株卡提供该入口（demo 专用），将花朵快进至盛放并展示旅程弹窗（五阶段递进 →「已盛放」→ 引导压花收藏）。

### F5 压花收藏与花房（P4）
- 花朵到达盛放后可「**压花收藏**」：花房库存对应（品种+颜色）数量 +1，植株从场景移除。
- P4 花房（底部上滑半屏卡）：双列网格展示库存（含 ×0 灰态项：灰化卡片 + 角标 x0）。
- **重新种植**：×0 灰卡提供「重新种植」——自动带入该花原有品种与颜色，新花从种子阶段重新培养（API 1.2 复种入参）。

### F6 AI 花束（P4 双入口 → P5）
- 花房「AI插花」打开动作面板，两个入口：
  1. **AI 推荐搭配**：先选择送花意图（情侣约会 / 毕业季 / 生日祝福 / 探望问候 / 日常惊喜）→ AI 根据现有花材给出组合建议与理由，并**赠送 1 种符合意图的花材**（不要求用户种植，标「赠送」）→ 确认后生成预览；
  2. **自由搭配**：用户自行多选花材（0–库存 朵）→ 生成预览。组合可能杂乱时给轻量建议（如「主色较多，可减少一种主色，花束会更柔和」）。
- 生成结果：**写实风格花束预览图 + 花材清单 + 简短搭配说明 + 包装建议**。
- 选中的品种和初始颜色是硬约束；AI 可补充赠送花材与中性配材，不得改变用户所选品种/颜色。
- **预览/试配不消耗花材**（库存快照校验，不足 409；赠送花材不校验）。

### F7 发送花店与电商原型页（P5 → P6）
- P5 除预览与清单外，提供：**包装建议**（随预览返回）、**用户备注**输入（选填）、**是否接受相似花材替代**选项（默认接受）。
- 「**发送花店**」：调用下单接口，事务内扣减花材（赠送花材不扣）+ 方案置 sent + 创建订单（落备注/替代选项），随后跳转 P6。
- **P6 抖音电商原型页为纯前端静态原型**：展示店铺条、商品卡（预览图、花材摘要含赠送标记、金额）、备注/替代选项、履约时间线四节点、送达横幅「收到同款鲜花花束，旅程闭环 🎉」；不接后端、不接真实交易；页脚「演示原型，不构成真实交易」。
- 服务端订单接口保留作为业务能力与测试口径，本期演示前端不展示实时订单状态。

### F8 演示重置（「重新体验」）
- 提供演示重置能力（API 1.15）：清空全部演示数据并重新播种（花园 1、双方资源归零、**预置花材**：玫瑰·红×2、洋甘菊·白×2、向日葵·黄×1），供下一位评委完整体验。入口位置见《前端设计规范》。

| 品种 | 可选颜色 |
|---|---|
| 玫瑰 | 红 / 粉 / 白 |
| 向日葵 | 黄 |
| 郁金香 | 红 / 黄 / 紫 |
| 洋甘菊 | 白 |
| 百合 | 白 / 粉 |
| 满天星 | 紫 / 白 |

图鉴 6 种享有精品画法与专属科普模板；识别、复种、花束搭配均**不限于图鉴**——图鉴外品种由通用画法（layered_round）+ 通用颜色表/稳定哈希兜底生成视觉资产与科普文案。

Mock VLM 按图片内容哈希确定性命中图鉴中的一种（品种+颜色），同一图片永远识别为同一结果；真实 VLM（火山方舟）自由识别任意品种。

## 5. 非目标（MVP 明确不做）

- 「广义的花」（刷 feed 识花形内容）：识别规则与浮标触发条件待定（上游 §8.2），本期不做。
- 真实抖音聊天接入（P-chat 为仿制演示页）。
- App 式全局底部 TabBar；多花园管理 UI（能力预留）；账号与登录。
- 真实支付与真实商家对接；P6 不接后端、不展示实时订单。
- 资源每日上限/产出频率校准、连续互动具体判定、花束配方规则库、支出/收入分段、长期运营玩法（共同培育记录/花束印章/节日入口）等上游未定项。

## 6. 验收标准

1. `pytest` 后端测试全绿；`npm run build` 前端构建通过。
2. 端到端脚本（`scripts/e2e_check.py`）按 API v0.2 链路全部通过。
3. 浏览器手工走查：P0 上传 → P1 分析 → P2 科普 →「进入花园」选择花园 → P-chat 模拟互动（双方入账）→ P3「我/TA」进度 → 我照料（提醒 TA 弹窗）→ TA 自动完成 → 成长动画 →「查看完整成长旅程」→ 压花收藏 → P4「AI 推荐搭配」（意图+赠送）与「自由搭配」→ P5 预览（搭配说明/包装/备注/替代）→「发送花店」→ P6 闭环；×0 灰卡「重新种植」；「重新体验」重置。

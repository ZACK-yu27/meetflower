# 抖音花园 MVP

两位好友把现实中拍到的花种进共同花园；日常聊天、视频分享和持续互动会积累**各自的**照料资源。**双方分别完成照料**后，花朵逐阶段盛放、压花收入花房，并可组合成一束由抖音本地花店制作的实体花——**拍照识花 → 聊天养成 → 压花收藏 → AI 花束 → 本地花店履约** 的端到端闭环 Demo。

> 聊天让关系持续，花让关系被看见，花束让关系落到现实。

本仓库为 MVP：在无抖音环境、无真实模型 API 的条件下，以**抖音内程序**的页面形态跑通最小闭环（页面栈导航，无 App 式底部 TabBar）。VLM / LLM / 生图能力均为 mock 适配器（接口与真实模型对齐，可整体替换）；聊天互动由 Demo 模拟器按钮产生。

## 闭环链路

```
相机拍照/相册上传(P0) → 识图分析动画(P1) → AI科普页(P2) →「进入花园」→ 选择花园卡
→ 仿抖音聊天页(P-chat)：互动模拟器获资源（水滴/阳光/养料，双人各自入账）
→ 花园场景(P3)：「我 / TA」并列照料进度 →「照料这朵花」（整组扣除，双方各完成一次）
  (花种→萌芽→幼苗→花苞→盛放，地栽版资产) →「压花收藏」入花房
→ 花房(P4)：「AI 推荐搭配」（选送花意图，AI 给组合+理由+赠送 1 种花材）或「自由搭配」
→ 花束预览(P5)：预览图+花材清单+搭配说明+包装建议+备注+接受替代（预览不扣花材）
→「发送花店」（此时扣花材，赠送花材不扣） → 抖音电商原型页(P6，静态演示) → 收到同款花束 🎉
```

## 快速开始

前置：Python 3.13+、Node 20+。以下为 Windows Git Bash 命令。

**一键启动前后端**（`npm run dev` 会同时拉起 uvicorn :8000 与 vite :5173，首次需先建 venv 装依赖）：

```bash
cd server
python -m venv .venv && source .venv/Scripts/activate   # 首次
pip install -r requirements.txt                          # 首次
cd ../web
npm install                                              # 首次
npm run dev        # 一键双端：http://localhost:5173 ，已代理 /api 与 /static 到 8000
```

> `web/scripts/dev.mjs` 会启动前先清理 8000/5173 的残留占用，退出时整树杀净，不留孤儿进程。如需单独启动后端：`cd server && uvicorn app.main:app --host 0.0.0.0 --port 8000`。

浏览器打开 `http://localhost:5173`：

1. **P0 相机页**拍照/上传花朵图片 → P1 分析动画 → **P2 科普页**查看品种与养护 →「进入花园」→ 选择「我和小葵的花园」种下；
2. 进入 **P-chat 仿抖音聊天页**：底部三个模拟器按钮（`互发消息`=双方各得水滴、`分享视频`=单方得阳光、`延续互动`=双方各得养料）积累**各自的**资源；
3. **P3 花园页**：点选花朵查看「我 / TA」并列进度 →「照料这朵花」（整组扣除个人资源）→ 你完成后弹出「提醒TA照料鲜花」；TA 资源达标后约 8 秒自动完成照料，双方齐即升入下一阶段（进入花园可见成长动画）；「查看完整成长旅程」可快进到盛放；
4. 盛放后「压花收藏」→ **P4 花房**：「AI 推荐搭配」（选送花意图，AI 给出组合+理由并赠送 1 种花材）或「自由搭配」多选花材 → **P5 花束预览**（搭配说明/包装建议/备注/接受相似替代，预览不扣花材）→「发送花店」（此时扣花材，赠送花材不扣）；
5. 花材 ×0 后保留灰态卡，可「重新种植」（带入原品种颜色从花种重养）；
6. 进入 **P6 电商原型页**（静态演示），收到同款鲜花花束，旅程闭环 🎉。P-chat 右上角「重新体验」可重置全部演示数据，供下一位评委完整体验。

## Demo 说明与边界

- **模拟互动**：真实环境中水滴/阳光/养料来自抖音聊天与分享事件；Demo 由 P-chat 底部三个模拟器按钮代替（`POST /api/v1/demo/interactions`），资源来源文案与产品口径一致。
- **双人照料**：每朵花的每个成长阶段，要求两人各自满足自己的资源条件并各点一次「照料这朵花」（整组扣除，无缓冲期）。TA 为虚拟人：资源达标后延迟 8 秒自动完成照料（`TA_CARE_DELAY_SECONDS`，`app/config.py` 可调）。
- **阶段数值**：按向日葵示例（每人）：花种→萌芽 水×2；萌芽→幼苗 水×3+光×1；幼苗→花苞 水×4+光×2+养×2；花苞→盛放 水×5+光×3+养×3。
- **真实模型（火山方舟）**：`server/app/ai_gateway/` 已接入真实模型——VLM 识花 / LLM 科普与推荐文案走 `doubao-seed-2-0-lite`（chat/completions），花束预览走 `doubao-seedream-5-0`（images/generations 写实花束摄影）。配置 `server/.env`（模板 `.env.example`，`AI_PROVIDER=ark` + `ARK_API_KEY`）即启用；未配置或 `AI_PROVIDER=mock` 时回落本地 mock（哈希识花 + 模板文案 + Pillow 合成），每次真实调用失败也会自动降级保证演示不中断。契约与配置细节见 docs/API.md §4/§4.1；成长阶段图仍为 Pillow 地栽版（需确定性与透明底，不走生图）。真实链路烟测：`server/.venv/Scripts/python scripts/ark_smoke.py`。时延优化：识花首响只做 VLM（`detail=low`），科普文案后台异步补齐（前端轮询 `GET /api/v1/recognitions/{id}`）；识花可用 `ARK_VLM_MODEL` 单独指定更快端点。
- **视觉资产**：成长阶段图统一为**地栽版**（透明底、土丘底座、无花盆），花园场景直接摆放；花朵特写（透明底花头）用于花房与花束合成。
- **电商页**：P6 为纯前端静态原型（演示数据集中在 `web/src/demo/shopDemo.js`），不调用后端接口、不接真实交易；服务端订单接口保留作为业务能力。
- **节奏调快**：TA 自动照料 8s、订单约 70s 送达，均为 Demo 数值（`app/config.py` 可调）。
- **预置花材**：启动播种与「重新体验」重置后，花房预置玫瑰红×2、洋甘菊白×2、向日葵黄×1，便于直接体验花束链路。
- **不做**：账号体系、「广义的花」（feed 浮标识别，规则待定）、资源每日上限、花束配方规则库、多花园管理 UI、真实支付与商家对接。
